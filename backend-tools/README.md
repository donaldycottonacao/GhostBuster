# GhostBuster - Backend Audio Processing Tools

This directory contains Python-based audio-processing and voice-synthesis scaffolding tools supporting the **GhostBuster** simulated-call application.

---

## Architecture & Responsibilities

The backend tools assist developers and content creators in preparing realistic, audio assets for tactical social escape simulations:

1. **`scripts/clone_peer.py`**: A modular script scaffold for taking speaker-consented audio samples and preparing voice model profiles.
2. **`scripts/text_to_speech.py`**: A modular script scaffold for generating emergency/escape dialogue audio clips using authorized voice models.
3. **`voice_samples/`**: Local storage for approved raw voice recordings (excluded from Git version control).
4. **`output_assets/`**: Destination directory for generated audio files (.mp3, .wav) before deployment to the frontend client assets (excluded from Git version control).

---

## Legal & Ethical Mandate

> [!CAUTION]
> **Consent is Non-Negotiable**: Voice cloning tools must only be used on recordings where the speaker has given explicit, documented consent. Creating impersonations of non-consenting individuals, committing fraud, or spoofing emergency/telecom services is strictly prohibited. All call screens generated by GhostBuster operate within an explicitly simulated local app environment and do not engage real telephony networks.

## Prerequisites

- **Python**: Version 3.10+ (tested on Python 3.11).
- **pip**: Version 23.0+.
- (Optional future) C++ Build tools / FFmpeg if running neural TTS engines locally.

## Setup & Virtual Environment

Follow these steps from the repository root:

### 1. Navigate to `backend-tools`
```bash
cd backend-tools
```

### 2. Create a Virtual Environment
- **On Windows (PowerShell):**
  ```powershell
  python -m venv .venv
  .\.venv\Scripts\Activate.ps1
  ```
- **On macOS/Linux:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```

### 3. Install Dependencies
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

## Execution Instructions

### A. Testing Script Syntax
Run Python compilation check across all scripts:
```bash
python -m compileall scripts
```

### B. Voice Cloning Scaffolding (`clone_peer.py`)
Run parameter inspection and validation (dry-run):
```bash
python scripts/clone_peer.py \
  --sample-path voice_samples/sample_recording.wav \
  --speaker-name "Alex" \
  --authorized-consent \
  --dry-run
```
*Note: The `--authorized-consent` flag is mandatory. The script will reject execution without explicit consent confirmation.*

### C. Text-to-Speech Dialogue Generation (`text_to_speech.py`)
Synthesize dialogue text using an authorized voice model:
```bash
python scripts/text_to_speech.py \
  --text "Hey, there is an urgent water leak in the apartment! Please call back immediately." \
  --voice-model "landlord" \
  --output-file output_assets/peer_landlord.mp3 \
  --authorized-voice \
  --dry-run
```

## Troubleshooting

- **`Missing speaker authorization error`**:
  Ensure you pass `--authorized-consent` or `--authorized-voice` when executing scripts. This enforces explicit adherence to ethical AI guidelines.
- **`File not found error`**:
  Ensure relative file paths are relative to your current working directory. Always execute scripts from either `backend-tools/` or supply absolute paths.
- **`PowerShell execution policy error`**:
  If PowerShell blocks activating `.venv`, run:
  ```powershell
  Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process
  ```
- **`Audio codec / backend missing`**:
  When full TTS neural engines (like Coqui or Tortoise) are introduced in later stages, ensure `ffmpeg` is installed on your operating system and added to your system PATH.
